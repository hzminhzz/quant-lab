## Ownership map

| Domain | Owns | Consumes |
|---|---|---|
| Principal decisions | Objectives, scientific policy, protected authority | Reviewable effects and their evidence |
| Data resolution | Semantic requirements, pinned artifacts, policy-derived contracts | Actual lake metadata and immutable policy |
| Research governance | Intent, conformance, novelty, candidate/lineage allowance, selection debt and exposure | Data/code identities and prior evidence |
| Scientific evaluation | Causal execution and frozen statistical/robustness/comparative tests | Admitted frozen candidates and ML4T |
| Evidence | Durable records/artifacts and their provenance | Finalized effects; no speculative approvals |
| Agent control — target | Situation, plans, action/receipt interface, continuation and resource coordination | Existing domain rules; never another scientific ledger |
| Release Authority — target | Authorized immutable runtime and protected decision consumption | Exact candidates, trusted verification and explicit grants |

## Reading and truth rules

- Current permissions come from the applicable operating contract and explicit
  authorization; a target design is not an approval.
- Current facts come from actual source, state and evidence. Surface disagreement
  between policy, documentation and implementation instead of silently choosing
  the convenient version.
- Preserve immutable reports and original outcomes. Add a correction or new
  scoped finding rather than retroactively making old evidence look current.
- Use VERIFIED / INFERRED / HYPOTHESIS / UNKNOWN for claims, and keep engineering,
  scientific qualification, deployment and trading authority separate.
- Proposed control operations are unavailable until advertised and verified.
  Use the current runbook's supported interface in the meantime.
