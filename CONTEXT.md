# Quant-Lab domain glossary

Canonical meanings for current research concepts and the proposed control design.
This is a glossary; procedures live in [AGENT_RUNBOOK.md](AGENT_RUNBOOK.md),
and target contracts in [the architecture](docs/ARCHITECTURE.md).
Terms marked **target** do not claim an implemented capability.

| Term | Meaning |
|---|---|
| Principal | The person who owns objectives, research policy and protected decisions |
| Agent | The directly operating assistant that proposes, executes and verifies work within authority |
| Objective | A question or desired result with an evidence-based completion condition and bounded scope |
| Hypothesis | A prospective, falsifiable economic thesis with its mechanism, counterparty/friction and declared test |
| Research intent | The immutable approved meaning and evaluation plan for a registered hypothesis, fixed before implementation/results |
| DataRequirement | A semantic statement of the data a thesis needs; it does not choose scientific costs, cutoffs or debt rules |
| Contract | The immutable evaluation conditions and data identity applicable to a study |
| Venue policy | Principal-controlled research standards used to derive contract conditions and selection groups |
| Candidate | A distinct frozen selectable implementation/configuration bound to an intent, data and evaluator identity |
| Operation | A governed unit of work with declared effects; scientific evaluation is admitted before outcomes are computed/exposed |
| Attempt | Recorded execution of an operation, including interrupted, failed and uncertain execution |
| Receipt | Durable evidence of an operation's admission, progress or disposition; its existence is not necessarily success |
| Finalized evidence | An outcome whose authoritative record and required immutable artifacts have been committed and reconciled |
| Lineage | Economically related hypotheses/candidates that share bounded research allowance |
| Selection group | Comparable research whose search history contributes to statistical selection correction |
| Selection debt | Retained research history that affects multiple-testing accounting; it survives names, failures and contract variants |
| Fixed robustness scenario | A prospectively declared non-selectable perturbation; choosing it as a strategy requires ordinary candidate governance |
| Benchmark | A preregistered executable comparator evaluated on the same eligible basis as an incremental candidate |
| Exposure scope | The underlying information actually made readable, including its dataset, time and universe; distinct from lineage and selection group |
| Frozen batch | Prospectively authorized membership and comparisons for one qualification exposure |
| Claim | In exposure accounting, a spent reservation to consume information; in knowledge, a proposition supported or limited by cited evidence |
| Technical blocker | A missing engineering/source/capability prerequisite; it is not a scientific verdict |
| Scientific rejection | Falsification under the recorded test and scope; a useful result that cannot be erased by retry |
| Inconclusive evidence | Evidence that cannot resolve the frozen question; neither a pass nor a confirmed rejection |
| Qualification | A governed scientific disposition supported by its required evidence; separate from deployment or trading permission |
| Situation snapshot — target | A bounded, attributed view of current facts, uncertainty, authority, work and relevant next actions |
| Action plan — target | A prospective set of typed effects bound to subjects, prerequisites, costs, authority and completion evidence |
| Decision packet — target | The exact reviewable proposed effect, evidence, limits and consequences to which an authenticated decision applies |
| Delegation grant — target | Explicit bounded authority delegated by the principal, with scope, limits, validity and revocation |
| Build identity — target | The immutable identity of a candidate executable and its dependencies/configuration |
| Verification evidence | Observed checks and their coverage/limitations for exact subjects; it does not confer authority |
| Release authorization — target | Permission to activate an exact build under a specified policy and grant |
| Release Authority — target | The separately controlled owner of release admission, protected grants and activation decisions |
| Active runtime | The executable actually serving or performing work, independently of the current development checkout |
| Finding — target | An evidence-linked statement with applicability, limitations, contradictions and revalidation conditions |
| Projection | A derived view of authoritative records; it cannot grant permission or replace those records |
| Reconciliation | Determining and recording the disposition of an uncertain effect from existing evidence, without replaying science |
| Accretion | Improvement of future decisions through reusable evidence, tests and scoped knowledge, while preserving their provenance |
